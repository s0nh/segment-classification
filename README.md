# segment-classification

## 일정

* 1 주차 (2025.11.6~2025.11.13)

  __각자 맡은 데이터 전처리__
  ```
  * 왕민 1, 4, 5 (회원 정보, 청구입금 정보, 잔액 정보)
  * 홍정표 6, 7, 8 (채널 정보, 마케팅 정보, 성과 정보)
  * 손혜성 2, 3 (신용 정보, 승인매출 정보)
  ```
  결측치 존재하는 독립변수 총 31개 처리
  
  ### 범주형 데이터
  트리기반 모델을 사용하여 모델링할 계획이기 때문에 원핫인코딩은 적용하지 않고 레이블 인코딩만 적용할 예정임
  1. 결측치를 `None`(문자열)으로 대체 또는 과반수를 차지하는 클래스가 있다면 그 클래스에 병합
  2. 모든 경우의 수에 대해 카이제곱 검정 → 통계량이 높은 케이스를 채택하여 결측치 채움
  

  ### 연속형 데이터

  1. 좌우 대칭이면 `mean` 비대칭이면 `median` 으로 대체
  2. 기존에 결측치였다는 사실을 나타내는 이진데이터를 추가함 
  3. 이진데이터에 대해서 카이제곱 검정 → 유의미한 결과가 나온다면 채택


## 분석 흐름

### 0. 데이터 파악

- 타겟의 분포가 불균형했음(A, B가 극단적으로 적었음)
- 의견 조율 과정에서 오버샘플링이 필요하다고 판단
- 800개가 넘는 변수로 인해 범주형 변수를 특성에 따라 구분하는 것이 현실적으로 불가능함(레이블 인코딩, 원핫인코딩)
- 따라서 불균형한 타겟 분류 문제에 적합하고, 자체 내장된 오버 샘플링 기능이 있고, 원핫인코딩 대신 레이블 인코딩을 해도 상관없는 트리 기반 앙상블 모델을 사용하는 것으로 합의함

### 1. 결측치 처리

  - 범주형 데이터
    - 결측치를 `None`으로 대체함
    - 결측치를 그대로 두는 방법, 다른 클래스에 병합하는 방법 중 검정 통계량이 더 높게 유지되는 방법을 선정하기 위해 초기 몇 변수에 대해서 통계검정을 실시함
    - 모든 경우에 대해 결측치를 그대로 두는 것이 검정통계량이 더 높게 나왔기에 남은 범주형 결측치 또한 그대로 남겨둠
  - 연속형 변수
    - 전체 데이터의 분포에 끼치는 영향을 최소화하기 위해 median 값으로 대체 후 새로운 이진 피처를 추가해서 결측치 정보를 유지함

### 2. 피처 엔지니어링
  #### 날짜 데이터
  - **원본 데이터 상태**  
  데이터에서 날짜 데이터는 yyyymmdd.0의 형태 즉 소수로 표현되어 있음  
  - **문제점**  
  20220101과 20211231은 실제로는 하루밖에 차이가 나지 않지만 소수로 표현된 상태에서의 차이는 훨씬 크게됨.(숫자의 크기 차이가 실제 시간의 흐름과 일치하지 않음)  
  - **변환 내용**  
  각 데이터가 수집된 날을 가리키는 변수 기준년월과 몇 달 차이가 나는지 확인하여 연속적인 형태로 변환함
  #### __R_M 변수
  - **원본 데이터 상태**  
  최근 N 개월 간의 고객의 카드 내역이 저장되어 있음(N은 1개월, 6개월, 12개월 등으로 존재함)
  - **문제점**  
  만약 최근 6개월 간의 수치가 7개월~12개월 간의 수치에 비해 압도적으로 높게 되면 최근 7개월~12개월 간의 데이터는 무의미해짐. (높은 상관관계가 발생 -> 다중공선성 문제 발생)
  - **변환 내용**  
  중복되는 독립변수 간 중복되는 정보를 제거함(R12M - R6M)

### 3. 독립변수 간 중복되는 정보 제거

  1. 연속형 변수 vs 연속형 변수  
  - 피어슨 상관계수를 구한 후 크기가 0.98 이상인 변수 쌍을 추출
  - 추출된 변수 쌍 중에 종속 변수와의 ANOVA 검정을 하여 검정통계량이 더 작은 변수를 탈락시킴

  2. 범주형 변수 vs 범주형 변수 
  - Phik 를 구한 후, 계수가 0.98이 넘는 쌍 선택.   
  - 종속변수 Segment와 카이제곱 검정을 통해 카이제곱 통계량이 낮은 독립 변수 탈락.   
  - 추가) Phik 구하는데 컴퓨터 메모리 부족, 시간 너무 오래 걸려서 라벨링 후, corr 상관계수 추출 후, 카이제곱분포 적용 (정확하지 않음)  
  - 추가) 크래머 v 계수를 사용해 상관관계 분석.

  3. 범주형 vs 숫자형   
  - Phik로 계수 구하고 어떤 독립변수 조합이 관련성이 강한지 알 수 있음.   
  - 하지만 서로 다른형의 독립변수는 종속변수(Segment)의 검정통계량 범위가 다르기 때문에 검정통계량만으로 선택 불가능.   
  - 따라서 비용이 많이 들고, 독립변수 간의 조합도 매우 많기 때문에 현실적으로 불가능. XGBoost의 성능을 믿고 상관계수 제거 안함.

### 4. 피처 엔지니어링 검증
  - ___B_M 데이터의 종속관계를 제거한 데이터와 그렇지 않은 데이터에 대해 별도의 튜닝을 하지 않은 XGB 모델을 이용하여 성능을 평가해봄
  - 성능 개선은 미미하지만, 위의 독립변수 간 상관관계 분석 과정에서 제거된 변수가 더 적었음
  - 즉 다중공선성 문제를 해결하고 데이터 전처리 과정에서 더 많은 정보를 보전할 수 있었음

### 5. 주요 변수 100개 선정
  - 별도의 튜닝을 하지 않은 XGB에 데이터를 학습시키고 가장 중요도가 높은 피처 20개를 시각화함
  - 피처 엔지니어링한 변수 중 상당수가 상위 20개에 포함됨
  - 이후에 중요도가 높은 변수 상위 100개를 추출
  - 추출한 100개 변수로 학습시킨 모델과 전체 변수약 600개로 학습시킨 모델의 성능을 비교함
  - 주요 피처 100개 선정 이후 f1-score가 0.001 하락함
  - 하지만, 모델의 학습 속도와 메모리 사용량이 개선됨
  - 다음 단계에서 진행할 모델의 하이퍼파라미터 조정 과정에서 시간을 단축할 수 있으며, 더 적은 변수로 단순화한 모델은 복잡한 모델에 비해 과적합 위험이 더 적으므로 상위 100개를 선정하는 것이 합리적인 판단임

### 6. 오버샘플링
  - LightGBM 모델의 `scale_pos_weight`과 `is_unbalance` 파라미터를 활용하여 A, B의 비중을 더 늘리려고 시도했으나 전체 40만개 데이터 중 A와 B가 500개도 채 되지 않아 학습이 충분히 되지 않음
  - 범주형 및 연속형 피쳐를 가진 데이터를 모두 처리할 수 있는 smote-nc(Nomial and Continuous) 알고리즘을 적용해 오버샘플링 적용.
  - smote-nc만 이용해 A, B 세그먼트를 2000개, C는 D 세그먼트와 개수가 같게 오버샘플링 진행.
  - 오버샘플링 후 모델을 학습시킨 결과, 오버샘플링 안 한 데이터로 학습한 모델보다 A세그먼트를 7개나 더 찾음. 하지만 B는 아직 하나도 찾지 못함.
  - 이를 개선하기 위해 smote-nc와 random oversampling 진행 (단순하게 데이터를 복사해서 오버샘플링하는 기법) -> A와 B 세그먼트는 Ramdom oversampling(데이터가 적기 때문), C 세그먼트는 데이터가 많기 때문에 smote-nc기법 적용
  - 복합적으로 적용한 결과 예측한 A세그먼트 개수 1개 감소(smote-nc만 적용했을 때 보다)
  - 추가적으로 predict 함수가 아닌 predict_proba 함수를 통해 각 클래스의 확률 리스트를 받고 A와 B 세그먼트일 확률이 threshold와 비교해 그 값을 넘으면 A, B 세그먼트로 예측하는 후처리 과정 진행.
  - 진행 결과 하나도 찾지 못했던 B 세그먼트 1개 발견, A세그먼트 개수 이전보다 7개 증가함(18개)
  - 오버샘플링은 smote-nc 알고리즘을 이용해 진행.

### 7. 모델 선정 및 학습
  - 하이퍼 파라미터 튜닝 : 우선순위 높은 피쳐 100개, smote 리샘플링, 가중치 적용 후 진행.
  - 총 3단계로 나눠서 하이퍼파라미터 튜닝 진행:
    1. 트리 모양 파라미터 튜닝 (max_depth, min_child_weight)
    2. 다양성을 위한 파라미터 튜닝 (subsample, colsample_bytree)
    3. 규제 튜닝 (gamma, reg_alpha, reg_lambda)
  - 교차 검증을 하면 과적합 문제를 예방할 수 있지만, 매 폴드마다 smote로 리샘플링을 하기 때문에 시간비용과 학습장비 문제로 진행 못함(hold out 방식으로 진행)

  - 최종모델 학습은 학습률 0.01, n_estimators 30000으로 해서 최대한 많이 학습
  - early_stopping을 50으로 해서 과적합 예방
  - A, B, C간의 특징이 비슷하다는 것을 혼동행렬로 확인해 이 셋 세그먼트를 분류하는 rule base 후처리 진행하려 함 
  - 후처리 적용 결과 recall은 올라갔지만 정밀도가 너무 떨어져서 rule base 후처리는 포기(임계값을 튜닝 할 수도 있었지만 그러면 validation data에 과적합이 날 수도 있어서 진행 안함).
  - 후처리를 진행하지 않은 이유 : 극단적인 데이터 불균형 상황에서 별도의 테스트 셋이나 임계값 튜닝용으로 데이터를 분리할 경우, 모델이 학습할 수 있는 희소 클래스의 정보가 손실되어 학습 안정성을 크게 저해할 수 있음. 따라서 별도의 후처리를 위한 데이터 분할 대신 최대한 많은 데이터를 학습에 활용하는 전략을 선택함.
  - 모델 성능 평가는 모델을 학습시킬 떄(early_stopping) 사용했던 validation data로 진행하였기에 이 점수가 실전에 그대로 적용되지 않을 것이라고 인지해야함.
